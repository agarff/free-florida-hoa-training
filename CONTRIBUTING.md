# Contributing

Use the suggestion link on a monthly guide or self-paced module to identify its exact edition. Describe the issue, propose precise wording and link to a public supporting source. Use fictional or anonymized examples. Leave resident details, addresses, account information and other private data out of suggestions and discussion.

Suggestions and discussion comments are reviewed before public display. An optional contact address is visible only to the owner. For a proposed change to be adopted, the owner reviews the source and approves exact text. An authorized maintainer edits the course in source control, changes only the affected edition, tests and publishes the update, then records the live edition in the change log. Approval records never edit or deploy the course.

The public repository is [agarff/free-florida-hoa-training](https://github.com/agarff/free-florida-hoa-training). Browse the code and lessons, [open an issue](https://github.com/agarff/free-florida-hoa-training/issues), or [propose a pull request](https://github.com/agarff/free-florida-hoa-training/pulls). The official site owner reviews proposed changes before they are adopted; a repository merge does not automatically deploy the website. Use the live site’s suggestion flow for the original course. For a copy of the site, use that copy’s maintainer channel. When submitting wording, share only material you have permission to contribute under CC BY 4.0. Original code contributions offered for inclusion should use MIT terms.

For code changes, run the build against a fresh database and check that migrations are additive when existing records are involved. See the [code of conduct](CODE_OF_CONDUCT.md) and [private security reporting](SECURITY.md).
